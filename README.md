# Mood Check-In

A small browser-based project made with basic HTML, CSS, and JavaScript for a class assignment.

## Original Idea

I wanted to make a simple mood check-in page for students. The page asks, "How are you feeling today?" and lets someone choose Calm, Overwhelmed, or Tired. Each choice shows a short supportive message and changes the page's colors. My goal was to keep the page clean and easy to use.

## How to Run

1. Keep `index.html`, `style.css`, and `script.js` in the same folder.
2. Open `index.html` in a web browser by double-clicking it.
3. Click a mood button to see its message and colors. You can switch moods at any time.

No installation or extra libraries are needed.

- `index.html` contains the question, buttons, and message area.
- `style.css` controls the layout, colors, and button styles.
- `script.js` updates the message and selected mood when a button is clicked.

## Reflection

*Draft for me to edit before submitting.*

The project matched my original idea because it has three mood buttons, different supportive messages, and a background that changes with each choice. The layout stayed simple. The first version did not make the moods feel as visually different as I wanted, even though the interaction worked.

I tested the page in my browser and confirmed that the interaction worked. After trying it, I asked for more distinct mood styles. The updated version uses green for Calm, peach for Overwhelmed, and lavender for Tired, with matching button and message colors. I wanted each choice to feel different without adding complicated features.

I also asked AI to check for bugs. Its simulated click checks passed for all three moods, including switching between them and clicking the same mood again. It reviewed the CSS too. It could not open the local file in its browser because of a security restriction, so that check did not confirm how the final page looked in a real browser.

AI helped me turn my idea into working files and make changes from my feedback. The comments and file explanations gave me a starting point for understanding the code. I still needed to decide what the project should do, whether the result matched my intention, and how much complexity was appropriate for the assignment.

I still need to check the final colors and layout on different screen sizes and browsers. I also want to review the supportive messages to make sure they sound natural to me. The automated checks give me some confidence in the interaction, but I still need to judge the final experience myself.
